Project

Super Mega Database

Fullstack searchable and sortable database for Super Mega Baseball 4.

Role

Solo project

Stack

React/Vite, FastAPI, PostgreSQL, SQLAlchemy

Links

Live site · Source

Overview

This serves as a helpful tool for completing in-game drafts. Having participated in online leagues for the game before, I'm aware of a desire for this kind of database that users can reference. I've been able to receive real user feedback and bug reports since launching, helping me get it refined.

What went into it

React was chosen over alternatives like plain html/js because the site needed to be interactive (player search, sortable tables, filtering) without constant full page reloads. Vite made production and testing much easier with its local dev server. I went with FastAPI over Node/Express because of the interactive API docs it generates. Testing the API before having to worry about the frontend allowed me to focus on one thing at a time. This was my first time working with SQL, so I learned the importance of ORMs, allowing me to define database tables in python classes rather than writing raw SQL. SQLAlchemy was the ORM I used. I chose to use PostgreSQL because the data being handled is all relational. Players belong to teams, traits belong to players, etc. Alembic was used to track changes to the database as migration files. The database is hosted on Neon, the frontend on Vercel, and the backend on Render.

Future Outlook

I'd like to add a login system and several user-specific features, like the ability to upload custom teams/players.
